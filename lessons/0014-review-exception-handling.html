복습: exception handling

레슨 0014 · 복습 세션 (큐 진행 아님, 0013 재확인) · 큐는 여전히 9/11, exception handling은 아직 체크 전

0013에서 checked/unchecked 개념은 결국 정확하게 정리했지만, try/catch 코드를 쓸 땐 예외가 나는 호출을 catch 안에 넣는 실수를 반복했다 — "실패하면 대안으로 다른 걸 한다"는 일반 조건 분기랑 헷갈린 것. 오늘은 새 개념 없이, ① 하루 지난 뒤 개념이 남아있는지 quick recall, ② try/catch 실행 흐름을 코드 없이 예측해보기, ③ 다른 도메인(Order/Payment)으로 hands-on을 처음부터 다시. 이번엔 힌트 없이 스스로 구조를 맞추는지가 관건이다.

Part 2 — try/catch 실행 흐름, 코드 없이 예측하기

아래 두 코드를 실행하지 말고, 눈으로만 읽고 뭐가 출력될지 채팅에 먼저 답한다. 그다음에 실제로 돌려서 맞았는지 확인한다. 

// 스니펫 A
try {
    System.out.println(riskyLookup(99L));   // 이 id는 존재하지 않음 → 예외를 던짐
} catch (NotFoundException e) {
    System.out.println("잡음: " + e.getMessage());
}
System.out.println("끝");
// 스니펫 B
try {
    System.out.println("safe call");        // 이 줄은 예외를 던지지 않음
} catch (NotFoundException e) {
    System.out.println(riskyLookup(99L));   // 예외를 던지는 호출이 catch 안에 있음
}
System.out.println("끝");

두 스니펫 각각 몇 줄이, 어떤 내용으로 출력될지 예측해서 채팅에 적어줘. B는 일부러 0013에서 나왔던 실수와 같은 모양으로 만들어뒀다.

Part 3 — Hands-on: OrderService, 처음부터 다시

practice/0014-review-exception-handling/p0014/에 시작 코드 없이 작성한다. 0013의 Employee/EmployeeService와 구조는 완전히 같지만, 오늘은 결제(payment) 도메인으로 바꾼다.

1) Order.java — field: id(Long), customerName(String), amount(double, 주문 금액). constructor, getter 세 개.

2) OrderNotFoundException.java — unchecked (RuntimeException 상속). String message constructor.

3) InsufficientBalanceException.java — checked (Exception 상속). String message constructor.

4) OrderService.java — field: Map<Long, Order> store. method 세 개:

  • Order save(Order order) — 저장하고 저장한 order 반환.
  • Order findByIdOrThrow(Long id) — 없으면 OrderNotFoundException을 throw. (throws 선언 필요 없음 — 왜인지 이젠 설명할 수 있을 것.)
  • void processPayment(Long orderId, double paymentAmount) throws InsufficientBalanceException — findByIdOrThrow로 주문을 찾은 뒤, paymentAmount가 주문의 amount보다 작으면 InsufficientBalanceException을 throw.

5) Runner.java — 순서대로:

  1. OrderService 생성, Order 하나 저장 (예: id=1L, amount=50000).
  2. 존재하는 id로 findByIdOrThrow 호출 → amount 출력. (try/catch 없이.)
  3. 존재하지 않는 id(예: 99L)로 findByIdOrThrow를 try/catch로 감싸서 호출 → catch에서 메시지 출력. 이번엔 힌트 없이 처음부터 올바른 구조로 써본다 (예외 나는 호출은 try 안에).
  4. processPayment(1L, 10000)(주문 금액보다 적은 결제)을 try/catch로 감싸서 호출 → catch에서 메시지 출력.
스스로 체크리스트:
  • 3번, 4번에서 예외가 날 수 있는 호출이 catch가 아니라 try 안에 있는가?
  • findByIdOrThrow엔 throws가 없고 processPayment엔 있는 이유를 코드를 안 보고 말할 수 있는가?
  • IDE가 자동으로 채워준 catch block 내용(있다면)이 실제로 원하는 동작(메시지 출력)인지 확인했는가?
