static vs instance

레슨 0006 · 문법 기초 큐 5/11 · 매번 쓰던 static이 뭐였는지

practice/0003-class-object-constructor/Money.java 맨 아래 public static void main(String[] args)를 다섯 번의 레슨 내내 그냥 지나쳤을 거야. Money의 다른 method들(add, getCurrency)에는 static이 없는데 main에만 있다. 왜 하나만 다른지가 이 레슨의 시작이다.

1. instance member — object마다 따로

지금까지 만든 currency, amountInCents 같은 field는 instance field다. money1과 money2는 서로 다른 값을 가진 완전히 별개의 currency, amountInCents를 갖는다. new Money(...)를 부를 때마다 메모리에 새로 만들어진다.

2. static member — class가 하나만 갖는다

static이 붙은 field는 object가 아니라 class에 속한다. 모든 instance가 같은 하나를 공유한다. Oracle 튜토리얼의 표현대로, static field는 "고정된 하나의 메모리 위치"에 저장되고 그 class로 만든 모든 object가 그걸 같이 본다. 

public class Ticket {
    private static int nextId = 1;   // 모든 Ticket이 공유하는 하나의 카운터

    private int id;                  // 각 Ticket마다 따로
    private String subject;

    public Ticket(String subject) {
        this.id = nextId;
        nextId++;                    // 공유 값을 갱신
        this.subject = subject;
    }
}

new Ticket(...)을 세 번 부르면 id는 세 개(1, 2, 3)가 따로 생기지만, nextId는 처음부터 끝까지 하나뿐이다.

3. static method는 object 없이 부른다

main이 static인 이유가 여기 있다. JVM은 프로그램을 시작할 때 아직 만들어진 object가 하나도 없다. object 없이 실행할 진입점이 필요해서 main은 static이어야 한다.

static method는 ClassName.methodName() 형태로 object 없이 바로 부른다. 그리고 중요한 제약이 하나 있다 — Oracle 문서 원문: "class method는 instance variable이나 instance method에 직접 접근할 수 없다 — object reference를 통해서만 가능하다. 또한 class method는 this를 쓸 수 없다 — 가리킬 instance 자체가 없기 때문이다." 

public static int getCreatedCount() {
    return nextId - 1;   // OK: static field
    // return subject;   // 컴파일 에러: instance field는 static에서 못 씀
}

4. static + final = 상수

static과 final을 같이 쓰면 "class 전체가 공유하는, 재대입 불가능한 값" — 즉 상수가 된다. Math.PI가 대표적인 예다. Oracle 문서: "final로 선언하면 재대입할 수 없고, 프로그램이 그걸 시도하면 컴파일 에러가 난다."

Quarkus Panache의 active record entity는 Person.findAll(), Person.findById(id)처럼 static method로 쿼리를 부른다 — object 없이 class 이름으로 바로. 반면 Spring Data JPA는 PersonRepository를 instance로 주입받아(@Autowired) repository.findAll()처럼 부른다. 같은 일을 하는데 하나는 static, 하나는 instance인 이유 — Spring은 repository 자체가 교체 가능한 object(dependency injection의 대상)이길 원하기 때문이다. Spring Boot로 가면 "쿼리 메서드는 주입받은 instance로 부른다"가 기본값이라고 생각하면 된다.

5. invoice-app에 바로 적용

DB 연결 없이 개발 중일 때, in-memory로 mock invoice를 만들면서 ID를 순서대로 붙여야 하는 순간이 온다 — 지금 만든 Ticket의 nextId와 똑같은 패턴이다. 나중에 실제 DB(@GeneratedValue)로 넘어가면 이 카운터는 필요 없어지지만, 그 전까지 mock repository를 만들 때 static counter는 실무에서 자주 나오는 임시 다리다.
