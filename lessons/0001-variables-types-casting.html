variables, types, type casting

레슨 0001 · 문법 기초 큐 1/11 · invoice-app 금액 처리와 직결

invoice-app에서 금액(price, total)을 다루려면 먼저 Java의 type이 어떻게 값을 저장하고, 언제 값이 손실되는지 알아야 한다. 이걸 모르면 "왜 0.1 + 0.2가 0.3이 아니지?" 같은 버그를 설명 못 한 채 그냥 넘어가게 된다.

1. variable은 무엇인가

variable은 값을 담는 저장 공간이고, 반드시 type을 가진다. Java는 statically typed 언어라서, variable을 선언할 때 type을 명시해야 하고 컴파일 시점에 검사된다. 

int quantity = 3;
String productName = "노트북";
double unitPrice = 1200.50;
Quarkus/Java에서도 이건 동일하다. TypeScript나 동적 언어와 달리, Java는 선언 시점에 type이 고정되고 바뀌지 않는다. Angular(TypeScript)에서 let x: number를 쓴 경험이 있다면 감이 비슷하다 — 다만 Java는 컴파일 후에도 이 규칙이 런타임까지 그대로 적용된다.

2. primitive type 8가지

Java에는 8개의 primitive type이 있다. 이건 객체가 아니라 언어 자체에 내장된 값 타입이다.

3. 왜 돈을 double로 다루면 안 되는가

double은 이진 부동소수점(binary floating point)이다. 10진수 소수(0.1, 0.2 같은)를 이진수로 정확히 표현할 수 없는 경우가 많아서 누적 오차가 생긴다. 

double a = 0.1;
double b = 0.2;
System.out.println(a + b); // 0.30000000000000004

invoice-app에서 100개 항목의 소계를 더하면 이 오차가 눈에 보이는 금액 차이로 쌓인다. 그래서 실무에서는 금액에 BigDecimal을 쓴다. BigDecimal은 10진수를 정확히 표현하는 별도 클래스다 — 이건 이후 레슨(collections/generics 이후)에서 다룬다. 지금은 "왜 안 되는지"만 기억해두면 된다.

기억할 것: int/long은 정수라서 오차가 없다. 문제는 double/float처럼 소수를 이진법으로 표현할 때 생긴다.

4. type casting

casting은 한 type의 값을 다른 type으로 변환하는 것이다. 두 방향이 있다.

widening (자동, 안전)

작은 type → 큰 type. 값 손실이 없어서 Java가 자동으로 해준다.

int quantity = 3;
double result = quantity; // int -> double, 자동

narrowing (수동, 위험)

큰 type → 작은 type. 값이 잘릴 수 있어서 명시적으로 캐스팅해야 컴파일이 된다.

double totalPrice = 1200.99;
int rounded = (int) totalPrice; // 1200 — 소수점 이하는 버려짐(반올림 아님)
Quarkus에서 REST 응답의 JSON 숫자를 Java 객체로 바인딩할 때, 타입이 안 맞으면 Jackson이 예외를 던지거나 조용히 반올림했던 경험이 있을 것이다. 그게 바로 narrowing 문제가 프레임워크 레벨에서 드러난 것이다.

5. invoice-app에 바로 적용

지금 invoice-app에서 항목 수량과 단가를 다룬다면:

  • quantity는 int — 수량은 정수, 소수가 될 이유가 없다.
  • unitPrice, total은 지금 당장은 double로 써도 되지만, "이건 나중에 BigDecimal로 바꿔야 한다"는 걸 인지하고 있어야 한다.
  • 수량 × 단가를 계산할 때 int * double은 자동으로 widening되어 double이 된다.
