collections — List, Set, Map

레슨 0009 · 문법 기초 큐 8/11 · 0008의 interface가 실제로 이렇게 쓰인다

0008에서 "interface는 계약, 구현은 class"라고 배웠다. List, Set, Map이 바로 그 예시다 — 셋 다 interface고, ArrayList/HashSet/HashMap이 그 구현체다. 오늘은 새 개념이 아니라, 이미 아는 개념(interface)이 실무에서 어떤 모습으로 나타나는지 보는 레슨이다.

1. List — 순서 있음, 중복 허용

List<String> tags = new ArrayList<>();
tags.add("food");
tags.add("food");     // 중복 그대로 허용됨
tags.get(0);           // index로 접근 — "food"

"An ordered collection... Unlike sets, lists typically allow duplicate elements." — Oracle Java Platform SE 8 — List

선언 타입은 List(interface), 실제로 만드는 건 ArrayList(구현체) — 0008에서 배운 "선언 타입 vs 실제 타입"이 여기서도 그대로 적용된다. <String>은 "이 List에 뭘 담을지" 지정하는 문법인데, 이건 generics 큐 항목에서 제대로 다룬다 — 지금은 <타입> 형태로만 알아두면 된다.

2. Set — 중복 없음, 순서 보장 안 함

Set<String> categories = new HashSet<>();
categories.add("전자제품");
categories.add("전자제품");   // 이미 있으므로 무시됨
categories.size();             // 1

"A collection that contains no duplicate elements." — Oracle Java Platform SE 8 — Set

List처럼 get(0)으로 index 접근이 안 된다 — Set은 "이 안에 있는지 없는지"만 중요하지, 순서를 보장하지 않는다.

3. Map — key로 value를 찾음

Map<Integer, String> nameById = new HashMap<>();
nameById.put(1, "김철수");
nameById.put(2, "이영희");
nameById.get(1);        // "김철수" — key로 즉시 조회
nameById.put(1, "김철수2");  // 같은 key면 덮어씀, 중복 key 불가

"An object that maps keys to values. A map cannot contain duplicate keys; each key can map to at most one value." — Oracle Java Platform SE 8 — Map

List에서 특정 id를 가진 요소를 찾으려면 전체를 순회(loop)해야 하지만, Map은 key로 바로 찾는다. "id로 조회"가 잦으면 Map을 쓰는 이유다.

4. 언제 뭘 쓰는가

ListSetMap
순서보장됨보장 안 됨보장 안 됨 (HashMap 기준)
중복허용불허 (자동 제거)key는 불허, value는 허용
쓰는 이유순서대로 쌓인 데이터, index 접근중복 제거, "포함 여부"만 필요id → object 빠른 조회
Spring Data JPA의 repository.findAll()은 List<Entity>를 반환한다 — DB row 순서를 유지하면서 중복(같은 PK를 가진 row는 없지만) 걱정 없이 쌓아야 하니 List가 맞는 선택이다. 반대로 "이미 처리한 주문 id들"처럼 포함 여부만 중요하면 Set<Long>을, "id로 캐시"가 필요하면 Map<Long, Entity>을 쓴다.

5. invoice-app에 바로 적용

영수증 하나에 항목이 여러 개면 List<LineItem> — 항목 순서가 중요하고 같은 이름의 항목이 중복될 수도 있다. 영수증에 붙은 태그(예: "출장", "식비")는 Set<String> — 같은 태그를 두 번 붙일 이유가 없다. 영수증 id로 빠르게 찾아야 하는 캐시가 필요하면 Map<Long, Receipt>이 맞다.
