lambda와 stream

레슨 0015 · 문법 기초 큐 11/11 (마지막 항목) · 0009에서 이미 실전으로 써본 것을 formalize

0009(collections) hands-on에서 아무도 시키지 않았는데 .stream().map().collect(Collectors.toSet())를 스스로 썼고, 각 단계를 정확히 설명했다. 그래서 오늘은 새로 배우는 레슨이 아니라 정리하는 레슨이다. 이미 쓸 줄 아는 map/collect는 "왜 이런 문법인지"(functional interface)만 짚고, 아직 안 써본 filter/sorted/reduce로 빈틈을 채운다. 이걸로 문법 기초 큐가 끝난다.

1. 이미 쓴 것 — 왜 그 문법이 동작하는가

0009에서 썼던 코드를 다시 보자.

Set<String> categories = products.stream()
    .map(p -> p.getCategory())
    .collect(Collectors.toSet());

p -> p.getCategory()가 lambda expression이다. Oracle 문서의 정의:

"A lambda expression consists of... a comma-separated list of formal parameters enclosed in parentheses... the arrow token, ->... a body, which consists of a single expression or a statement block." — Oracle Java Tutorials — Lambda Expressions

파라미터가 하나면 괄호도 생략 가능해서 p -> p.getCategory()처럼 쓴다. 이 lambda가 map()의 인자로 들어갈 수 있는 이유는, map이 받는 타입이 functional interface이기 때문이다.

"A functional interface is any interface that contains only one abstract method." — Oracle Java Tutorials — Lambda Expressions

0008에서 배운 interface 개념이 여기서 그대로 이어진다 — map(Function<T, R> mapper)의 Function은 abstract method가 apply() 하나뿐인 interface다. lambda p -> p.getCategory()는 사실 apply(p)를 구현한 익명의 구현체를 한 줄로 쓴 것이다. "interface는 계약, 구현은 class(또는 lambda)"라는 0008의 원칙이 여기서도 동일하다.

2. Stream pipeline — 세 부분

"A pipeline contains the following components: A source... Zero or more intermediate operations... A terminal operation." — Oracle Java Tutorials — Aggregate Operations 

products.stream()          // source
    .map(p -> p.getCategory())   // intermediate — 새 stream을 반환
    .collect(Collectors.toSet());  // terminal — stream이 아닌 결과를 반환

핵심 구분: intermediate operation은 stream을 반환하므로 계속 이어붙일(chain) 수 있고, terminal operation은 stream이 아닌 최종 결과(Set, List, 숫자 등)를 반환하며 여기서 파이프라인이 끝난다. collect가 terminal이라 그 뒤에 .map()을 또 이어붙일 수 없는 이유가 이것이다.

3. 오늘 새로 채우는 것 — filter, sorted, reduce

filter — 조건에 맞는 것만 남김

List<Product> expensive = products.stream()
    .filter(p -> p.getPrice() > 10000)   // Predicate<T> — true/false 반환
    .collect(Collectors.toList());

"Returns a stream consisting of the elements of this stream that match the given predicate." — Oracle Java Platform SE 8 — Stream

sorted — 정렬

List<Product> byPriceDesc = products.stream()
    .sorted(Comparator.comparingDouble(Product::getPrice).reversed())
    .collect(Collectors.toList());

Product::getPrice는 method reference — p -> p.getPrice()를 더 짧게 쓴 것뿐, 의미는 동일하다.

reduce — 여러 값을 하나로 합침

double total = products.stream()
    .mapToDouble(Product::getPrice)   // Stream<Product> → DoubleStream
    .sum();

// reduce로 직접 쓰면:
double total2 = products.stream()
    .map(Product::getPrice)
    .reduce(0.0, (acc, price) -> acc + price);   // identity=0.0, accumulator

"Performs a reduction on the elements of this stream, using an associative accumulation function..." — Oracle Java Platform SE 8 — Stream

실무에서는 합계처럼 단순한 경우 mapToDouble().sum()을 더 자주 쓰고, reduce는 "각 단계에서 누적값(accumulator)을 직접 다뤄야 하는" 좀 더 일반적인 경우에 쓴다. 오늘 hands-on에서는 둘 다 연습한다.

4. 한눈에 정리

operation종류하는 일
filterintermediate조건(Predicate)에 맞는 것만 남김
mapintermediate각 요소를 변환(Function)
sortedintermediate정렬(Comparator)
collectterminalList/Set/Map 등으로 모음
reduceterminal전체를 하나의 값으로 누적
forEachterminal각 요소에 부수효과(출력 등)
Quarkus/Spring 양쪽 다 service layer에서 이 패턴이 그대로 나온다 — repository.findAll().stream().filter(...).map(...).collect(Collectors.toList())는 controller에 List를 그대로 넘기지 않고 조건에 맞는 것만, 원하는 형태(DTO)로 가공해서 넘길 때 쓰는 표준 패턴이다.

스스로 체크리스트:
  • filter 안의 lambda는 true/false를 반환하는가? (Predicate)
  • map 안의 lambda는 하나의 값을 다른 값으로 바꿔 반환하는가? (Function)
  • collect가 이 체인의 마지막에 오는가 — 그 뒤에 또 stream operation을 이어붙이지 않았는가?
