`practice/0003-class-object-constructor/Money.java`의 field를 다시 봐 — String currency;, int amountInCents;. 앞에 아무 키워드도 없다. 반면 `practice/0004-review-class-object-constructor/PageRequest.java`에서는 private int pageNumber;처럼 private를 직접 붙였다. 왜 둘이 다른지, 그리고 그 차이가 왜 중요한지가 이 레슨의 전부다.

출처: Oracle Java Tutorials — Controlling Access to Members of a Class

2. Money의 field가 private이어야 하는 이유

0003에서 Money의 constructor는 음수 금액이면 예외를 던지도록 짜여 있다 — fail fast였다. 그런데 field에 아무 modifier도 없으면(package-private), 같은 package 안의 다른 코드가 constructor를 거치지 않고 field에 직접 접근해서 값을 바꿀 수 있다. 

Money money = new Money("USD", 100); // constructor가 검증함 — 안전
money.amountInCents = -999;          // field가 열려있으면 검증 없이 그냥 덮어써짐!

constructor에서 아무리 invariant를 지켜도, field가 열려있으면 그 뒤에 아무 데서나 규칙을 깨고 들어올 수 있다. private로 막아야 "이 object는 항상 유효한 상태"라는 보장이 constructor 이후에도 계속 유지된다.

3. 그럼 값은 어떻게 꺼내나 — getter

field를 private로 막으면, 외부에서 값을 읽을 방법이 없어진다. 그래서 읽기 전용 접근을 public method로 열어준다 — 이게 getter다. 

public class Money {
    private String currency;
    private int amountInCents;

    // constructor는 기존과 동일...

    public int getAmountInCents() {
        return amountInCents;
    }

    public String getCurrency() {
        return currency;
    }
}

값을 바꾸는 setAmountInCents(...) 같은 setter는 일부러 안 만든다 — Money는 한 번 만들어지면 안 변하는 게(immutable) 의도다. 0004의 PageRequest.nextPage()가 this를 바꾸지 않고 새 object를 반환했던 것과 같은 이유다.

Quarkus의 Panache entity는 보통 field를 public으로 그냥 열어둔다 (active record 패턴 — 편의가 우선). 반면 Spring Data JPA 스타일은 거의 항상 field를 private로 막고 getter/setter(또는 Lombok)로 접근한다. 같은 ORM 문제를 다른 철학으로 푸는 것 — Spring Boot로 넘어가면 private + getter가 기본값이라고 생각하면 된다.

4. protected와 package-private은 지금은 가볍게

protected는 inheritance(다음 큐 항목)에서 subclass가 parent의 member에 접근할 때 쓴다 — 지금은 존재만 알아두면 된다. package-private(modifier 없음)은 "같은 package 안에서만 협업하는 클래스들" 사이에 쓰는데, Spring Boot 프로젝트에서는 패키지 구조를 세밀하게 나누기 전까지 자주 등장하진 않는다.

5. invoice-app에 바로 적용

Invoice, LineItem 같은 class의 field는 전부 private로 시작하고, 꼭 필요한 것만 getter로 연다. status를 바꾸는 method가 필요하면 setStatus(String status)를 무작정 여는 게 아니라, "DRAFT에서 PAID로 못 건너뛴다" 같은 규칙을 그 method 안에서 검증하게 만든다 — constructor에서 했던 fail fast를 method에도 똑같이 적용하는 것이다.

Hands-on: Money를 private로 고치기

practice/0003-class-object-constructor/Money.java를 직접 연다. 새 파일을 만들지 않고 기존 파일을 고친다.

  • field 두 개(currency, amountInCents) 앞에 private를 붙인다.
  • getCurrency(), getAmountInCents() getter 두 개를 추가한다.
  • main에서 System.out.print(money2.add(money3).amountInCents)처럼 field에 직접 접근하던 코드를 getter를 쓰도록 바꾼다 — getAmountInCents().
  • 확인: main 어딘가에 money1.amountInCents = -999; 같은 줄을 일부러 추가해보고, 컴파일이 안 되는 걸 직접 확인한다 (에러 메시지 읽고 나서 그 줄은 지운다). private가 실제로 막아준다는 걸 눈으로 보는 게 목적이다.
