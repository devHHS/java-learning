레슨 0002 · 문법 기초 큐 2/11 · 복습 위주 · invoice-app 상태 처리와 직결

if/for/while은 이미 Quarkus에서 매일 썼으니 빠르게 넘어간다. 이 레슨의 진짜 목적은 classic switch의 fallthrough 함정과, invoice-app에서 status(초안/발송/결제완료 등)를 다룰 때 쓸 Java 14+ switch expression이다. 이건 Quarkus 경험만으로는 안 잡히는 부분이다.

1. if / for / while — 빠른 복습

문법은 대부분 언어와 동일하다. 확인만 하고 넘어간다.

if (quantity > 0) {
    // ...
} else if (quantity == 0) {
    // ...
} else {
    // ...
}

for (int i = 0; i < items.size(); i++) {
    // 인덱스가 필요할 때
}

for (Item item : items) {
    // enhanced for — 인덱스 필요 없을 때, invoice-app에서 대부분 이 형태
}

while (hasNext) {
    // 조건이 유지되는 동안
}
Quarkus/Java에서 이미 매일 쓰던 문법 그대로다. 다른 게 있다면 TypeScript의 for...of ↔ Java의 enhanced for가 거의 1:1 대응한다는 것 정도.

2. classic switch — fallthrough 함정

Java의 전통적 switch는 break를 안 쓰면 다음 case로 흘러 내려간다(fallthrough). 이건 의도한 동작이 아니라 실수로 버그를 만드는 가장 흔한 원인 중 하나다. 

String status = "SENT";
switch (status) {
    case "DRAFT":
        System.out.println("초안");
        // break 없음!
    case "SENT":
        System.out.println("발송됨"); // 여기서 시작
        // break 없음!
    case "PAID":
        System.out.println("결제완료"); // 여기까지 같이 출력됨 — 의도한 게 아니면 버그
        break;
    default:
        System.out.println("알 수 없음");
}

위 코드는 status가 "SENT"일 때 "발송됨"과 "결제완료"를 둘 다 출력한다. 각 case가 독립적으로 동작하길 원하면 매 case마다 break를 빠뜨리지 않아야 한다.

출처: Oracle Java Tutorials — The switch Statement

3. switch expression (Java 14+) — fallthrough 없음

최신 Java는 -> 화살표 문법의 switch expression을 지원한다. 이건 값을 반환하고, case 간 fallthrough가 구조적으로 불가능하다 — 실수의 여지를 문법 자체가 없애버린 것. 

String label = switch (status) {
    case "DRAFT" -> "초안";
    case "SENT" -> "발송됨";
    case "PAID" -> "결제완료";
    default -> "알 수 없음";
};

여러 줄이 필요하면 yield로 값을 반환한다. 

int priorityScore = switch (status) {
    case "DRAFT" -> 0;
    case "SENT" -> {
        System.out.println("독촉 대상 확인 필요");
        yield 5;
    }
    case "PAID" -> 10;
    default -> -1;
};
기억할 것: classic switch는 statement(실행만 함, break로 제어), switch expression은 expression(값을 만들어 돌려줌, fallthrough 없음). invoice-app에서 status에 따라 값을 정하는 로직은 switch expression을 쓴다.

4. invoice-app에 바로 적용

인보이스 status(DRAFT, SENT, PAID, OVERDUE)에 따라 화면에 보여줄 라벨이나 색상을 정하는 로직은 switch expression으로 짜면 fallthrough 버그 걱정 없이 깔끔하게 나온다. line item 목록을 순회하며 합계를 낼 때는 enhanced for가 기본이다.
