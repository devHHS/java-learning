패턴

public interface DiscountPolicy {
    double apply(double amount);          // 몸통 없음
}

public class PercentageDiscount implements DiscountPolicy {
    private double percent;
    @Override
    public double apply(double amount) {
        return amount - (amount * percent / 100);
    }
}

public abstract class PaymentMethod {
    protected String accountId;
    public PaymentMethod(String accountId) { this.accountId = accountId; }

    public boolean validate() { return accountId != null; }   // 몸통 있음 — 공유됨
    public abstract void process(double amount);               // 몸통 없음 — 강제됨
}

고르는 기준 (Oracle 원문 요약)

abstract class: 서로 밀접한 class끼리 코드를 공유해야 할 때, 공통 field/method가 많을 때, public이 아닌 접근 수준이 필요할 때.

interface: 서로 관련 없는 class들이 구현할 때, "무엇을 하는지"만 규정하고 싶을 때, 한 class가 여러 계약을 동시에 만족해야 할 때.

Spring 다리

JpaRepository가 interface인 이유 — "무엇을 하는지"만 규정하면, Spring이 런타임에 구현체를 대신 만들어줄 수 있다. 구현을 신경 안 써도 되는 게 interface의 핵심 이점.
